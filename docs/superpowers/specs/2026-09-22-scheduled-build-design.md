# 工程每日定时打包设计规格

## 1. 目标与范围

在现有 AB2 构建工具上增加"每个工程可开启每日定时打包"能力：配置开关和触发时间（如凌晨 4:00），到点自动发起构建。

范围：

- 定时配置保存在 Agent 本机工程配置中，Agent 配置页提供开关和时间设置。
- 调度由 Agent 端执行，不依赖 Manager 在线。
- 定时构建复用现有执行链路（Git 同步、XLua、Unity 打包、失败分析）。
- Manager 在线时任务和日志正常展示；离线时本地继续构建，但该次任务不在 Manager 留下记录。

非目标：补跑错过的任务、每天多次触发、按渠道分别定时、Manager 端集中调度。

## 2. 配置模型

工程配置新增可选字段：

```json
"schedule": { "enabled": true, "time": "04:00" }
```

- `enabled`：布尔开关。
- `time`：`HH:MM`（00:00–23:59），按 Agent 本机时间触发。
- Agent 配置页每个工程显示"每日定时打包"开关和"打包时间"输入框；保存后立即生效，无需重启。

校验规则（`AgentConfig.save_project`）：`enabled` 必须是布尔；开启时 `time` 必须匹配 `HH:MM`。

## 3. 调度与执行

Agent 服务启动时运行独立的 `_schedule_loop` 协程，每 20 秒检查一次：

1. 项目中 `schedule.enabled` 为真且当前分钟等于 `schedule.time`；
2. 当天该工程尚未触发过；
3. 该工程当前没有活动任务（定时任务与手动任务共用一个"活动工程"集合）。

满足后取工程第一个启用渠道，并按渠道 `branch_filter` 计算分支列表取第一条（与 Manager 页面预选一致：`default` 过滤为工程默认分支，其余为最新版本分支）；分支列表为空则跳过。

触发后生成 Agent 侧任务 ID：

- Manager 在线：先发送 `task_created` 消息，Manager 按当前连接补齐 `agent_id` 并插入 `queued` 任务行，随后事件流正常写入日志/阶段/产物。
- Manager 离线：本地继续执行，事件直接丢弃；重连后不补传当次记录（已确认的取舍）。

## 4. Manager 改动

- WebSocket 新增 `task_created` 消息处理：按当前连接补齐 `agent_id`，`INSERT OR IGNORE` 写入任务行，重复注册不产生第二条。
- 前端每轮询周期恢复各渠道最新任务（不再只在 Agent 快照变化时恢复），保证 Agent 主动创建的定时任务 5 秒内出现在卡片上。
- 手动创建任务时若该工程已有活动任务，返回 409 和明确错误信息，而不是 500。

## 5. 边界与恢复

- 到点工程无启用渠道、分支过滤结果为空：跳过，不产生失败任务。
- 到点工程正在构建：跳过本次，不排队、不补跑。
- 每天最多触发一次，内存记录触发日期；Agent 进程在触发分钟内重启可能重复触发，由"活动工程"保护兜底。
- Agent 重启后定时配置从 `agent.json` 恢复。

## 6. 测试策略

- `schedule_due` 纯函数：开关、时间匹配、边界（00:00、23:59）。
- `_due_schedules`：到点触发、同日去重、工程忙跳过、无渠道跳过、禁用不触发。
- 配置校验：非法时间、非布尔开关被拒绝。
- Manager `register_task`：插入任务行、重复注册幂等。
- 手动验证：把时间设为下一分钟，观察 Manager 卡片出现 running 任务。
