AB2 AI 失败原因分析

**结论：本次 Unity AB2 资源打包失败。**

**关键证据**

- 打包命令入口为 `HLS_Editor.ExportEditor.BuildFromAB2`，参数是 `-ab2Agent android_dev`，见日志第 22-34 行。
- Unity 脚本编译失败：
  - 第 328 行：`ExitCode: 3`
  - 第 7430 行：`*** Tundra build failed`
  - 第 7431 行：`## Script Compilation Error`
  - 第 8376 行：`Scripts have compiler errors.`
  - 第 8377 行：Unity 以 `return code 1` 退出
- 主要错误集中在 XLua 自动生成文件：
  - `Assets/Games_Logic/ThirdPlugins/XLua/Gen/DelegatesGensBridge.cs(7795,30)`：找不到 `Happy_BuYu.GlobalVO.BigWinPerformType`
  - `(17684,26)`：找不到 `Happy_BuYu.Game.BY_FishMaxWinBreakthroughManager`
  - `(19631,26)`：找不到 `Happy_BuYu.Game.BY_MissileChoosePanel`
  - `(26864,37)`：找不到 `Happy_BuYu.Game.FishComing.FishComingAvoidanceBlocker`
  - `(29715、29737、29759、29781、29809)`：找不到多个 `FishComing` 相关类型：
    - `FishComingLevel`
    - `FishComingHighPanelStyle`
    - `FishComingPerformanceType`
    - `FishComingDefinition`

**根因判断**

根因是 **C# 脚本编译失败，且 XLua 生成代码引用了当前工程中不存在或未被当前程序集编译的类型**。

`DelegatesGensBridge.cs` 中确实存在这些类型引用，例如：

- 第 7795 行引用 `Happy_BuYu.GlobalVO.BigWinPerformType`
- 第 17684 行引用 `Happy_BuYu.Game.BY_FishMaxWinBreakthroughManager`
- 第 29715-29809 行引用多个 `Happy_BuYu.Game.FishComing` 类型

由于脚本编译未通过，Unity 无法正常执行后续 AB 打包入口。对照打包工具代码：

- `ExportEditor.BuildFromAB2()` 会根据 `-ab2Agent android_dev` 创建 Android Dev Proxy，见 `ExportEditor.cs:40-68`
- `PlatformProxyAndroidDev.BuildAsset()` 只有在成功进入执行阶段后，才会调用 `HybridCompile.CompileHybridDLL()` 和 `AssetBundleBuilderWindow.ExportAB()`，见 `PlatformProxy.cs:93-103`

本次日志中没有出现 `HybridCompile`、`ExportAB`、`CreateAssetZip` 或资源上传成功标记，说明 **尚未进入实际 AB 资源导出阶段**，不是导出过程中的资源错误。

**非根因信息**

- Unity 许可证相关错误出现在第 3、4、13 行，但后续显示已成功更新许可证并解析 entitlement，不是本次失败原因。
- Shader fallback 缺失警告出现在第 167-177 行，目前属于警告，不是导致本次退出的直接原因。
- `.meta` 文件 GUID 解析警告出现在第 235-270 行，也不是本次最终失败原因。
- 大量 `CS0612`、`CS0108`、`CS0436` 等为编译警告；真正阻断编译的是上述 `CS0234` 错误。

**建议修复步骤**

1. 检查当前分支 `dev/8-2-26` 中上述类型对应的源代码是否被删除、改名、移动，或未纳入 `Games_Logic_Assembly.asmdef`。
2. 检查 XLua 生成代码是否与当前 C# 源码版本不一致，重点确认：
   - `Assets/Games_Logic/ThirdPlugins/XLua/Gen/DelegatesGensBridge.cs`
   - XLua 的生成配置、委托注册配置及生成标记
3. 根据工程规范重新生成 XLua 代码。打包工具中已有生成逻辑：
   - `CSObjectWrapEditor.Generator.GenAll()`
   - `XLua.DelegateBridge.Gen_Flag = true`
4. 生成后执行一次 Unity AssetDatabase 刷新和脚本编译，确认所有 `CS0234` 消失。
5. 仅在 Unity 控制台无脚本编译错误后，重新执行 AB2 打包。
6. 重新打包时应确认日志出现 `HybridCompile`、`ExportAB` 或 `ExportABInternal`，并最终出现资源导出及压缩成功标记。

当前工程分支已确认是 `dev/8-2-26`。
